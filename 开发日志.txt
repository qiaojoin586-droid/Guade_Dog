## 一、项目概述

### 1.1 项目定位

导盲AI智能体是一款面向视障人士的全方位 AI 辅助应用。以**语音交互**为核心入口，集成**视觉感知**、**导航避障**、**安全求救**、**生活服务**、**政策咨询**五大能力，通过多 Agent 协作分工，为视障用户提供"听得到、走得稳、用得安全"的智能出行与生活体验。

### 1.2 技术栈

| 层 | 技术选型 |
|----|---------|
| 前端 | Vite 5 + React 18 + TypeScript(strict) + Tailwind CSS + zustand + axios + PWA |
| 后端 | FastAPI + SQLAlchemy 2.0(async) + Pydantic v2 + Alembic |
| 数据库 | MySQL 8（aiomysql 驱动） |
| LLM / 视觉 | 阿里云百炼千问（qwen-max 文本 / qwen-vl-max 视觉），可切换讯飞星火 |
| 语音 | 讯飞 ASR / TTS（WebSocket），前端 Web Speech API 原型 |
| 地图导航 | 高德开放平台 API（逆地理编码 + 步行路线规划 + 直线距离查询） |
| 天气 | 和风天气 API（已接入，未指定城市时按 GPS 坐标自动定位） |

### 1.4 团队分工（"四人分工" Agent 编排设计）

按照设计方案，系统拆分为 4 个核心 Agent + 1 个 LLM 路由核心（Orchestrator），每人负责一个模块：

| 成员 | 负责模块 |
|------|---------|
| 人A（Conversation 负责人） | 对话模块 + Orchestrator 路由核心 + ASR/TTS 语音链路 |
| 人B（wang1998929g9） | 导航模块（定位、距离查询、路线规划、高德 API 对接） |
| 人C（shen） | 安全模块（药品识别、健康问答、钞票识别、SOS） |
| 人D | 感知模块（天气、提醒、OCR、政策追问） |

## 五、代码分析（架构与模块关联）

### 5.1 整体架构

系统采用 **MVP 单体后端 + 多 Agent 模块化**架构，遵循"演进式设计"：先跑通最小闭环，后期再向 Agent 编排/微服务演进。

```
用户（前端 React）
   │  HTTP（axios，/api 代理到后端 8000）
   ▼
FastAPI 应用工厂（main.py）
   ├── 中间件：request_id 全链路追踪（X-Request-ID 沿用/生成）
   ├── 统一异常处理（HTTPException → 统一错误码体系）
   ├── auth / users 路由（JWT 鉴权）
   └── 4 个 Agent 模块路由（每模块一行挂载，集成点清晰）
          │
          ▼
   Orchestrator（LLM 路由核心，骨架阶段为规则路由表）
          ├── Conversation Agent（对话/ASR/TTS/工具链）
          ├── Navigation Agent（高德定位/距离/路线）
          ├── Safety Agent（药品/健康/钞票/SOS）
          └── Perception Agent（天气/提醒/OCR预留）
```

### 5.2 关键实现逻辑

**（1）Agent 契约与路由（core/agent_protocol.py + orchestrator.py）**
- 所有 Agent 实现统一契约 `handle(req: AgentRequest) -> AgentResponse`，字段包含 intent / params / user_id 与 text / action / data / needs_followup；
- Orchestrator 维护 intent → 模块映射表（如 weather/ocr/vision/reminder → perception，location/navigation/distance → navigation，health/medicine/currency/sos → safety），未匹配意图回退 conversation；
- 当前为硬编码规则路由，LLM 动态意图分类标记为 TODO——这是"规则优先保证可控，再逐步智能化"设计原则的体现。

**（2）语音闭环（conversation 模块）**
- 前端 useVoiceRecorder 采集麦克风音频 → speechService 上传；
- asr.py 通过讯飞 WebSocket 流式识别为文本 → chat.py 调用 LLM（双供应商：DashScope OpenAI 兼容接口 / 星火 WS，由 LLM_PROVIDER 配置切换）→ tools.py 解析 JSON 结构化工具调用并真实分发到对应 Agent（orchestrator 路由）→ tts.py 合成语音返回；
- 工具的结构化结果与动作标识（tool_data / action）经 chat API 透传前端，供 UI 触发后续动作（如 SOS 上报、导航跳转）；
- LLM 客户端（core/llm.py）统一封装 json_mode（DashScope 用 response_format=json_object，星火用系统提示词约束 + chat.py 容错解析）。

**（3）安全模块三能力（safety 模块）**
- vision.py 统一封装 qwen-vl-max 视觉调用，medicine/currency 复用；
- 三条安全红线落在代码里：医疗免责声明必播、识别图片不落盘不落日志（隐私）、钞票置信度宁严勿松（不播错金额）；
- VisionError 异常体系统一降级：未配置 Key 返回业务码 50020/50021 而非崩溃，前端文案与后端降级码一一对齐。

**（4）导航模块（navigation 模块）**
- amap.py 封装高德逆地理编码（坐标 → 结构化地址）与步行路线规划（返回分段指引）；
- 新增 distance 意图："有多远"用球面直线距离（haversine）回答，不依赖步行规划，远距离目的地不再受 TOO_FAR 限制；
- 诚实定位：浏览器定位精度（accuracy）随坐标透传，按来源（GPS/IP）与精度阈值（1km）分档生成播报措辞，避免跨市误报；
- 前端 NavigationPage + useNavigationStore 管理定位与路线状态。

**（5）感知模块（perception 模块）**
- 天气查询支持"未指定城市"场景：优先用前端 GPS 坐标逆地理编码取城市，定位失败才追问；刻意不用 IP 粗定位（城市级精度且常跨市错误）；
- 自动定位所得的播报如实说明依据（"根据您的当前位置…"），与诚实定位原则一致。

**（6）配置与错误体系**
- config.py 三级优先（环境变量 > config.yaml > 默认值），敏感密钥只允许进 backend/.env（.gitignore 排除）；
- errors.py 统一错误码（4xxxx 客户端 / 5xxxx 服务端），main.py 统一异常处理器把异常映射为带 request_id 的标准响应体。

### 5.3 前后端协作模式

- 前端服务层（services/）与后端 API 一一对应（safetyService ↔ /safety/*，navigationService ↔ /navigation/*，speechService ↔ /speech/*）；
- zustand store 按模块拆分（useSafetyStore / useNavigationStore / usePerceptionStore 等），页面只消费 store；
- vite 开发服务器将 /api 代理到后端 8000，CORS 放行本机与局域网（支持手机真机联调）。

### 5.4 测试策略

- 后端测试全 mock、不触网（conftest.py 统一夹具），覆盖认证、语音链路、安全三功能、导航（含距离查询/定位措辞）、天气/提醒、orchestrator 路由等，共 24 个测试文件约 2,286 行；
- 前端以 `tsc --noEmit` 严格类型检查作为门禁；
- 测试代码与业务代码比例约 1:2.3，测试文化良好。
